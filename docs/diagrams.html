Diagrams

The README, the docs site, and the pages in docs/ draw Janus with these diagrams, each in a light and a dark version that follow the reader's colour scheme. A diagram is here when a picture says something better than a paragraph: how the parts fit, what happens over time, or why a rule is the way it is.

Where Janus sits​

Claude Code talks only to Janus; Janus sends most requests to Anthropic, the ones its rules choose to LM Studio, and records each in the ledger.

Shown in the README and the user guide. Source: architecture.html, architecture-dark.html.

What happens to one request​

The path one request takes, from the local-only check to the ledger. A request the local-only policy keeps local never takes a path to Anthropic: if the local model cannot answer it, Janus refuses it rather than following the "no / down" arrow.

Shown in the README. Source: request-flow.html, request-flow-dark.html.

Why a block once sent never changes​

Each turn resends the whole conversation, and what was sent before is read from the prompt cache cheaply. Change an earlier block and it, and everything after it, is written to the cache again at twenty times the price, which is why Janus never does.

Shown in What Janus changes. Source: prompt-cache.html, prompt-cache-dark.html.

A secret’s round trip through the guard​

With redaction on, Claude sees only a placeholder, uses it in a tool call, and Janus puts the real secret back before Claude Code acts.

Shown in The guard. Source: redaction.html, redaction-dark.html.

One five-hour window, with pacing and a stand-in​

As a usage limit fills, a pacing rule moves subagents to the local model first, the outage stand-in takes the main conversation once the limit is reached, and Janus notes when Claude takes over again.

Shown in Pacing. Source: usage-window.html, usage-window-dark.html.

What local-first costs in time​

A local answer is held back while it is checked, and a rejected one makes Claude Code wait for both models.

Shown in Local first. Source: local-first.html, local-first-dark.html.

Where Janus keeps things​

What points at what: Claude Code at Janus, the service at the binary and the config, the config at the log folder, and what is in that folder.

Shown in Installing. Source: where-things-live.html, where-things-live-dark.html.

Where a problem can be​

The four links a request depends on, numbered, with the check that looks at each. Finding which one failed comes before fixing anything.

Shown in Troubleshooting. Source: where-it-fails.html, where-it-fails-dark.html.

What a turn costs as the conversation grows​

The median cost of a main-conversation turn by context size, over a week of real use. Turns over 600k tokens were an eighth of the turns and a third of the cost, which is why a /compact between tasks pays.

Shown in Using Janus. Source: context-cost.html, context-cost-dark.html.

Where Janus’s trust boundaries are​

Your machine, the internet, and your network, and what crosses between them: the credential to Anthropic over HTTPS, and, if LM Studio runs elsewhere, plain HTTP to it.

Shown in The threat model. Source: trust-boundaries.html, trust-boundaries-dark.html.

How they are made​

The HTML files are the source. They were made with the diagram-design skill in the Ris Ink style: warm paper, ink, a single rose accent, teal for traffic to Anthropic, set in Fraunces and JetBrains Mono. The repo's .diagram-design file (profile: ris-ink) makes the skill use that style for every diagram drawn here; the profile itself lives in ~/.diagram-design/profiles/ris-ink.md, copied from the Ris-Ink design system on claude.ai. Each dark version is its light one with the profile's light-to-dark rule applied: ink and paper swap, and rose and teal lift to #e24a8a and #5ba3b8. In full, every colour in the light file becomes its dark one, and nothing else changes but the -dark in the <title> and <desc> ids:

LightDark
#faf6ef paper#1a1614
#fffdf8 raised paper#241c19
#1a1614 ink, and rgba(26,22,20,x)#f4ecdd, and rgba(244,236,221,x)
#6b625a muted, and rgba(107,98,90,x)#a89e8f, and rgba(168,158,143,x)
#776e65 soft, and rgba(119,110,101,x)#948b7d, and rgba(148,139,125,x)
#CB0162 rose, and rgba(203,1,98,x)#e24a8a, and rgba(226,74,138,x); a 0.08 tint becomes 0.10
#1a5b6e teal, and rgba(26,91,110,x)#5ba3b8, and rgba(91,163,184,x)

Each SVG is exported from its HTML with that skill's export_svg.py --system-fonts, so it loads no web fonts and makes no network request. Edit the light HTML, make the dark one from it again, then export both.

Draw new diagrams the same way, not in Mermaid, so that every picture in the docs is in the same style.
